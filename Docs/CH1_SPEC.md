어둑 — 챕터 1 버티컬 슬라이스 제작 명세서
한국 전통설화 1인칭 공포게임 「어둑」 · Unity · AI 제작(블렌더 MCP + 유니티 MCP) · 최종본 (2026.10)
이 문서는 「어둑」 통합 Spec(최종본, 2026.10)의 챕터별 상세 참고 자료다. 내용이 Spec과 다르면 Spec이 우선한다. 최종 확정 사항: 빛은 여우구슬이 낸다, 이동은 걷기·뛰기·앉기, 강공격 대신 숨 참기(챕터 2부터), 챕터 1은 산 아래 평지 0m·약풍, 첫 플레이 2.5~3.5시간.
표기: [확정] 기획서/조작키 설정서/대화에서 정해진 것. 이 문서의 모든 제안값은 사용자가 확정했다. 개정(2026.10): 빛은 화면 왼쪽 위의 여우구슬이 내도록 바꿨으며, 통합 Spec의 수치를 반영했다. 수치는 플레이 테스트 후 조정할 수 있으며, 조정 시 사유를 기록한다.
0. 목적과 범위
목적: 챕터 1(우물)만 끝까지 플레이 가능하게 만들어, AI 제작 파이프라인(블렌더 → 유니티)이 실제로 돌아가는지 검증한다.
포함: 현대 오프닝(우물 촬영) → 타임리프 → 우물 스테이지 → 기본 조작 튜토리얼 → 어둑시니 첫 등장과 시선 규칙 체험 → 마지막 컷(뒤돌아보면 우물 위의 어둑시니).
제외: 정화, 구슬 호출(길 안내), 전투, 보스, 인벤토리 상세, 지도, 일지, 챕터 2 이후 전부. 여우구슬의 빛과 위급 깜빡임은 챕터 1부터 포함한다.
시점 [확정]: 전 구간 1인칭. 주인공 전신 모델과 전신 애니메이션은 만들지 않는다(손, 캠코더, 화면 왼쪽 위에서 빛나는 여우구슬만 보임).

3. 챕터 1 진행 흐름
현대 오프닝: 밤, 우물 앞. 캠코더 촬영 시점. 윤민호가 “이상하게 여기만 계속 생각나더라” 대사(음성 또는 자막).
구미 조우: 우물가에 희미한 한복 차림의 여인 등장. 경고 대사. 플레이어가 캠코더로 우물을 줌(상호작용)하면 타임리프 컷.
우물 스테이지 진입: 17세기, 어둡고 좁은 우물 내부/주변. 구미가 자신의 여우구슬을 빛으로 건넨 뒤 조작 안내: 이동, 시점, 여우구슬 빛, 상호작용, 눈 감기.
탐색 구간: 우물 바닥과 주변 오브젝트 조사. 카메라 LCD에 갓 쓴 작은 형체(복선)가 찍힘.
어둑시니 첫 등장: 규칙 체험. 안 보면 작아지고, 보면 커지고 빨라진다는 것을 학습. 잡히면 즉사([확정])이므로, 첫 등장 거리를 멀게 하고 초기 속도를 낮게 두어 규칙을 이해할 시간을 준다(4.6 챕터 1 전용 수치 참조).
마지막 컷: 출구에 도달해 뒤돌아보면 우물 위에 서 있는 어둑시니. 암전. 챕터 1 종료.
4. 시스템 명세
4.1 1인칭 컨트롤러
이동/뛰기/앉기(숨기), 마우스·우스틱 시점. 앉은 상태에서 방향키를 누르면 앉은 채 이동한다. 자세별 속도와 소음 [개정: 걷기 3.0 / 뛰기 5.0 / 앉아서 이동 1.5 m/s, 소음 반경 6 / 15 / 3m]. 뛰기는 앞 방향만, 앉으면 카메라 1.0m.
헤드밥은 약하게, 옵션으로 끌 수 있게 [확정].
카메라 높이 1.6m 기준.
4.2 여우구슬 빛 (F)
화면 왼쪽 위(뷰포트 x≈0.18, y≈0.82)에 떠 있는 여우구슬이 빛난다. 구슬 위치에서 전방 Spot Light(12m, 55°)와 주변 Point Light(2m)가 나온다. F / 패드 Y 짧게로 켜기·끄기, 꺼도 구슬 자체 발광 10%는 남는다. 배터리 없음 [확정].
어둑시니는 여우구슬 빛을 비춰도 아무 효과가 없다 [확정]. 빛은 시선 판정과 무관하다.
위급 깜빡임: 어둑시니가 20m 이내면 여우구슬 빛이 느리게(2Hz), 10m 이내면 빠르게(6Hz) 깜빡이고 패드가 진동한다. 추격 중에는 항상 빠르게 깜빡인다. 방향 정보는 주지 않는다 [확정].
등장: 타임리프 직후 구미가 손바닥 위에 구슬을 띄워 민호의 왼쪽 어깨 위로 보낸다. 프롤로그(현대)에는 구슬이 없어 빛은 달빛과 캠코더 나이트비전뿐이다 [확정].
4.3 캠코더 (B로 켜기/끄기)
켜면 우측 하단 또는 손에 든 LCD가 보이고, 나이트비전 톤(녹색/노이즈)이 적용된 RenderTexture 표시.
배터리 소모는 챕터 1에서 없음 [확정]. 시스템 구조만 넣어 둔다.
복선 연출: 특정 지점에서 LCD에만 작은 실루엣이 보이고, 2차 확인 시 더 커져 있음(스크립트 트리거).
4.4 눈 감기 (V 누르고 있기 / LT)
누르는 동안 화면 암전(눈꺼풀 애니메이션 0.2초). 시선 판정에서 “보고 있지 않음”으로 처리.
지속 시간 제한 [확정]: 최대 4초 후 강제로 눈이 떠짐, 재사용 쿨타임 3초. 챕터 1에서는 튜토리얼 용도.
4.5 상호작용 (E)
화면 중앙 레이캐스트(거리 2m). 대상 위 프롬프트 표시. 짧게 누르기만 사용(길게 누르기는 챕터 2 정화용, 비활성).
4.6 어둑시니 시선 시스템 (핵심)
판정 방식: 매 프레임(또는 0.05초 간격) 어둑시니의 바운딩 지점 몇 곳이 플레이어 카메라 시야각 안에 있고, 사이에 가리는 콜라이더가 없는지 확인해 isSeen 값을 만든다.
파라미터 | 값 [확정]
보이는 판정 시야각 | 카메라 FOV 기준 화면 중앙 약 70%
가시 판정 대상 지점 | 머리, 가슴, 발 3점 중 1개 이상 보이면 true
보일 때 크기 증가 | 초당 +0.35 배율 (최대 3.0배)
안 보일 때 크기 감소 | 초당 −0.15 배율 (최소 1.0배)
보일 때 이동 속도 | 기본 1.2 m/s → 크기 3.0배에서 최대 3.6 m/s
안 볼 때 이동 | 2.0 m/s로 계속 접근한다. 여우구슬은 거리만 깜빡임으로 알리고 방향은 알려 주지 않는다
잡히는 거리 | 1.2m 이내 → 즉사 [확정]. 사망 연출 후 마지막 체크포인트에서 재시작(4.8)
눈 감기 중 | isSeen = false 처리
캠코더 LCD로 볼 때 | isSeen = true [확정]: LCD에 어둑시니가 보이는 동안(캠코더 켬 + LCD 카메라 시야 안)에도 직접 볼 때와 똑같이 커지고 빨라짐
챕터 1 전용 튜토리얼 수치 [확정]: 첫 등장 거리 15m 이상, 최대 크기 2.0배, 최대 속도 2.4 m/s(1.2 × 배율)로 제한해 즉사 전에 규칙을 파악할 시간을 준다. 이후 챕터에서 제한을 푼다.
설계 메모 [확정]: 어둑시니를 커지지 않게 확인하는 우회 수단은 없다. 직접 봐도, 캠코더 LCD로 봐도 커진다. 따라서 기획서의 “LCD/구슬 간접 확인 = 우회 수단” 표현은 더 이상 쓰지 않는다. 대응 수단은 시선을 돌리기(눈 감기, 고개 돌리기), 숨기, 이동, 지형·차폐물 활용, 결계(챕터 3)로 한정한다. LCD는 나이트비전과 복선 연출용, 여우구슬은 챕터 1부터 빛과 위급 깜빡임, 챕터 2부터 길 안내를 맡되, 어둑시니의 위치나 방향을 정확히 알려주지 않는다.
가시성 규칙 [확정]: 어둑시니는 투명하거나 은신 상태가 아니라 항상 눈에 보이는 실체다. 시선을 두면 커지고 빨라지는 것이 규칙일 뿐, 보이지 않게 숨는 능력은 없다. 구현 [확정]: 어둠 속에서도 실루엣이 식별되도록 몸 주위에 은은한 짙은 보라·남색 안개(약한 emissive/파티클, 채도 낮게)를 두어, 여우구슬 빛을 꺼도 시야에 들어오면 알아볼 수 있게 한다. 이 경우 공정성은 “보이는 순간 이미 규칙이 작동한다”는 긴장으로 성립하므로, 접근 사운드는 시야 밖 접근을 알리는 보조 단서로 둔다.
크기가 커질수록 도포 자락이 그림자처럼 번지는 효과(셰이더 파라미터 또는 머티리얼 블렌드).
접근 시 저주파 사운드 + 심장박동 SFX가 거리 기반으로 증가.
4.7 구미 (NPC, 챕터 1)
반투명 실루엣 또는 간단한 모델. 우물가와 우물 스테이지에서 안내 대사만 수행.
챕터 1에서 구슬로 변하지 않는다. 대신 자신의 여우구슬을 민호에게 빛으로 건네고, 반투명한 사람 모습으로 안내한다. 대사 톤은 친절하지만 계산된 목적 중심.
4.8 체크포인트 / 사망 처리
어둑시니에게 잡히면 즉사 연출(화면 암전 + 사운드) 후 마지막 체크포인트에서 재시작.
체크포인트는 챕터 1 안에서 3~4곳 [확정]. 우물 진입 직후, 탐색 구간 중간, 어둑시니 첫 조우 직전, 출구 직전.
자동 저장은 체크포인트 통과 시.
4.9 UI/HUD (최소)
대사는 자막만으로 시작 [확정]. 음성은 추후 녹음. 대사 데이터에 audioClip 필드와 화자 이름 필드를 미리 만들어 두고, 비어 있으면 자막만 표시. 음성이 생기면 코드 수정 없이 연결.
상호작용 프롬프트, 자막, 캠코더 LCD 오버레이(REC 표시, 배터리 아이콘은 자리만).
일시정지(Esc)와 설정 화면(키 리바인딩, 볼륨, 헤드밥 on/off).
4.10 지형과 이동 물리 [개정]
지형: 챕터 1은 산 아래 평지(고도 0m)다. 걷는 면의 경사 0~3°, 최대 5°. 바닥은 짚·마당흙과 흙길. 산 정상(사찰)은 500m로, 마을 뒤로 산이 높게 보이게 원경을 둔다.
이동 자세: 걷기(3.0 m/s, 소음 반경 6m), 뛰기(5.0 m/s, 소음 15m, 앞 방향만, 챕터 1은 스태미나 없음), 앉기(앉은 상태에서 방향키로 앉은 채 이동 1.5 m/s, 카메라 1.0m·충돌체 1.2m, 소음 3m, 높이 1.3m 이하 통로 통과).
레벨 규칙: 무너진 담 밑에 앉아서 지나는 틈을 1곳 이상 두어 도주로로 쓴다.
바람: 산 아래라 약풍(기본 세기 0.2, 40~60초마다 돌풍 +0.2). 나무·안개·구미의 댕기와 어둑시니 도포가 흔들린다. 돌풍 뒤 3초간 안개가 걷혀 멀리 있던 어둑시니가 갑자기 보일 수 있다. 여우구슬 빛과 어둑시니는 바람의 영향을 받지 않는다.
경사·바닥 재질 보정, 내리막 미끄러짐, 바람 규칙은 통합 Spec 3.10·3.11을 따른다. 어둑시니는 지형과 바닥 재질의 영향을 받지 않는다.

사실적 룩에서도 어둑시니는 실루엣 위주로 만든다. 얼굴이 어둠에 잠기는 설정과 어두운 조명 덕에 세부 모델링 부담이 크게 줄고, 섬뜩함도 유지된다. 구미(현대 모습)도 투명 셰이더로 처리해 사실적 인체 모델링을 피한다.
6. AI 작업 지침 (블렌더 MCP / 유니티 MCP에 그대로 전달)
6.1 공통
작업 전 이 문서를 먼저 읽고, 확정 값을 변경할 때는 사유를 기록한다.
한 번에 하나의 에셋/시스템만 작업하고, 완료마다 결과를 요약해서 보고한다.
불명확하면 추측하지 말고 질문한다.
6.2 블렌더 (에셋)
단위: 미터, 스케일 1.0 적용(Apply Scale) 후 내보내기.
축: Y-up으로 내보내기(FBX 설정), 정면은 -Z 또는 +Z 중 하나로 통일.
네이밍: SM_<이름> (스태틱), SK_<이름> (스켈레탈), M_<이름> (머티리얼), T_<이름>_<D/N/R> (텍스처).
룩 [확정]: 사실적. 폴리 예산 [확정]: 소품 2,000~10,000 tri, 환경 모듈 3,000~15,000 tri, 어둑시니 20,000 tri 이하.
머티리얼: PBR(Albedo/Normal/Roughness), 텍스처 해상도 2048 기본, 주요 에셋만 4096.
AI 제작 팁: 사실적 룩은 AI가 절차적으로 만들기 어려우므로, 돌·흙·나무 같은 표면 텍스처와 배경 소품은 무료 PBR 소스(Poly Haven 등)나 블렌더 MCP가 지원하는 에셋 라이브러리 연동을 활용하고, 직접 모델링은 고유 소품 위주로 한다.
원점: 오브젝트 원점은 바닥 중앙.
출력: /Assets/Art/<카테고리>/ 하위에 FBX와 텍스처.
6.3 유니티 (게임 로직)
폴더: Assets/Art, Assets/Scripts, Assets/Scenes, Assets/Prefabs, Assets/Audio, Assets/UI.
스크립트 구조: 시스템별 분리 — PlayerController, BeadLight, CamcorderController, GazeSystem, DarknessEnemyAI, InteractionSystem, EyeCloseController, DialogueUI.
입력: Input Actions 에셋 하나로 통합, 키 코드 직접 참조 금지.
수치: 4.6의 표 값을 ScriptableObject나 인스펙터 노출 필드로 만들어 코드 수정 없이 조정 가능하게.
씬: Ch1_Intro(현대), Ch1_Well(17세기) 두 개로 분리하거나 하나의 씬에서 전환(구현 단순한 쪽).
성능 목표 [확정]: 중급 PC 1080p 60fps.
7. 완료 기준 (체크리스트)
☐ 키보드+마우스와 Xbox 패드 모두로 처음부터 끝까지 플레이 가능
☐ 오프닝 → 타임리프 컷 → 우물 스테이지 → 마지막 컷까지 진행 가능
☐ 캠코더 LCD가 작동하고 복선 실루엣 연출이 나온다
☐ 어둑시니가 직접 보거나 LCD로 봐도 커지고 빨라지며, 안 보면(눈 감기 포함) 작아진다
☐ 잡히면 즉사 연출 후 마지막 체크포인트에서 재시작된다
☐ 대사가 자막으로만 나오고, audioClip 필드는 비어 있어도 오류가 없다
☐ 키 리바인딩이 동작한다
☐ 여우구슬 빛, 앉기(앉은 채 이동), 고개 내밀기, 상호작용이 동작한다
☐ 여우구슬이 어둑시니와의 거리에 따라 깜빡이고(20m·10m·추격), 방향 정보는 주지 않는다
☐ 접근 사운드와 기본 후처리 룩이 적용되어 있다
8. 결정 현황
확정 - LCD로 어둑시니를 볼 때도 크기 증가, 커지지 않는 우회 수단은 없음 - 챕터 1에서 어둑시니에게 잡히면 즉사 (체크포인트 재시작) - 그래픽 룩: 사실적 - 대사는 자막만으로 시작, 음성은 추후 녹음 - 여우구슬이 빛을 내는 유일한 광원
챕터 2 시작 전에 정리 - 챕터 5 두억시니 장소, 마패의 행방 등 스토리 충돌 항목  (구슬 역할은 통합 Spec 4.2로 정리됨: 광원, 위급 깜빡임, 체력 표시, 길 안내, 보스 퇴마·흡수)
제안값 전체 확정 - 4장 시선 시스템 수치, 이동 속도, 눈 감기 지속 시간·쿨타임, 체크포인트 개수, 기술 스택, 폴리 예산, 성능 목표 등 이 문서의 모든 수치 - 수치는 인스펙터에서 조정 가능하게 구현하고, 플레이 테스트 후 바꿀 때는 사유를 기록
